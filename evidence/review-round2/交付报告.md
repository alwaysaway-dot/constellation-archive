## 性能取证：发现与未发现

条件：Apple M2、macOS 26.6.2，Chrome 155.0.8059.85，ANGLE Metal（真实启用 WebGL）。390×844 以 DPR 3 模拟布局，1440×900 为桌面视口；渲染器原有像素比例上限仍为 1.5。此条件不是手机 GPU。

比较基线是正式站六份 HTML/JS/CSS 的逐字节一致副本，在本机 4190 端口提供；修改版为本机 4185。相同浏览器、硬件和程序化原生纵向滚动路径，分别包含首页停留、首次进入、稳定星图滚动、停留、反向、再次进入与快进快退。首个跨阶段 rAF 间隔已排除，避免把截图等待计入转场耗时。操作方式是自动化滚动，不是真实手指或触控板测量。

实际发现：

1. **稳定星图仍提交全部顶点后才在着色器内剔除远处粒子。** 本轮在初始化时按原始 Y 排序，稳定镜头用二分区间设置 drawRange。所有粒子、形状、动画参数保留；转场保留完整几何。300px 余量覆盖原有着色器 210px 的剔除边界，单元测试验证正反向/边界滚动。
2. **焦点 effect 在暂停/激活变化时重新测量布局，且滚动中反复写入相同焦点属性。** 现在仅在焦点或提示状态变化时写入；布局监听保留尺寸变化处理；ResizeObserver 负责画布尺寸，移除重复 window resize 路径。
3. **减少动态切换后，缓存的旧星图起点使粒子和 DOM 标签错位。** 390×844 同条件验证：基线首节点误差约 844.002px，修改后约 0.002px。现在绘制与焦点都使用统一的原生滚动起点/转场跨度。
4. **静止时重复计算相机姿态。** 相机姿态只在进度、尺寸或减少动态状态改变时更新；粒子内部活动继续运行。

检查到已有机制有效，继续保留：

- 首页停留时星图绘制为 0；稳定星图时首页绘制为 0。交接期间两者短暂重叠是现有空间衔接所需，并非重复创建的整套场景。
- 实测滚动/交接阶段粒子 bufferData 上传为 0，没有逐帧几何重建。
- 已有着色器编译与一次预热发生在初始准备阶段；本次没有证据显示交接瞬间重复初始化。
- 原生 scroll 决定相机进度，没有加入第二套平滑或延长转场。
- 页面不可见、减少动态及路由退出已有停绘/释放机制。退出后保存的旧渲染器引用计数不再增长。

### 同条件记录

以下取 `before-final/performance.json` 与最终代码的 `after-release/performance.json`，不是录屏帧率：

| 指标 | 基线 | 预览 |
| --- | ---: | ---: |

| 1440px 稳定星图停留提交粒子 | 23,081 | 7,277 |
| 390px 首次接近 rAF 间隔 P95 | 16.8ms | 16.8ms |
| 390px 接近终点最大 rAF 间隔 | 33.3ms | 16.8ms |
| 390px 首次接近 getBoundingClientRect 次数（含一次测量脚本读取） | 3 | 1 |
| 两宽度操作路径内 >34ms 间隔 | 0 | 0 |
| 两宽度操作路径内 >50ms 主线程长任务 | 0 | 0 |
| 操作路径 bufferData 上传 | 0 | 0 |

**不能据此宣称手机卡顿已解决。** 桌面 M2 本身没有稳定复现用户报告的持续掉帧，单次 33.3ms → 16.8ms 也不足以证明普遍改善。确认的是提交工作量和重复布局工作减少。

初次加载仍有长任务：390px 基线记录 99/97ms，预览 93/114/66ms；1440px 基线 97/92/90ms，预览 86/129/72ms。CPU 采样在启动期看到同步布局、WebGL 上下文创建、Three.js 初始化和垃圾回收；没有把全部启动长任务归因于某个单一函数，也没有把它们声称已消除。本轮未引入复杂资源线程改造。GPU 时间没有单独计时，无法从 rAF 或 JS 提交耗时判断手机 GPU 压力。
