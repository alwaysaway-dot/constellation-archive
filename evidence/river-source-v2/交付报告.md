## 实现与范围

- `src/river-handoff.ts`：共享源头位置、投影切线、上移比例及桥接曲线。支流起点位于现有莫比乌斯带面 `u=3.2 / v=0.3`，终点始终与第一首锚点对齐。
- `src/MobiusJourney.tsx`：一次原生滚动进度协调源头上移、支流延伸、星象凝聚及文字显现。入口按钮、手动滚动、反向滚动共用路径。
- `src/MobiusRenderer.ts`：取消原来的整体放大/散开/淡出，保留原半扭转模型、粒子分布、初始视角及主要交互；只在支流源头局部增强，并校正上移后的输入坐标。
- `src/vertical-lane-model.ts`：三层星链、不同星象分布、亮星等级及局部暗隙。固定种子可复现，不逐帧随机重建。
- `src/VerticalLaneRenderer.ts`：同一批材质绘制星链与星象，局部传递、深度微视差、各星象时间响应、离场释放、静态投影。
- `src/VerticalStarMap.tsx`：保留导航/焦点稳定区/单击进入/快速定位/返回位置，增加静态支流；修复“定位第一首时退回首页交接区”的边界问题。
- `src/river-source.css`、`src/main.tsx`：局部样式接入，星象上方有空间、标题下置并保持清楚；编号索引移至标题区右侧，避开下方作品文字。
- `wrangler.river-source-preview.jsonc`、`package.json`、`scripts/prepare-cloudflare.mjs`：单独预览 Worker 与构建指纹。
- `evidence/river-source-v2/`：复现脚本与交付记录。

89 个受保护的原有源码/内容/正式素材/音频文件逐字节匹配本轮基线。未改写歌曲、顺序、封面、正文、歌词、播放器波浪、其它作品及试听、专辑规则。没有新增依赖或公开技术说明模块。

## 十首星象

| 编号 | 可见轮廓 | 时间/聚焦响应 |
| --- | --- | --- |
| 01 | 两个精细亮核与错开的双股星流 | 交替传递，保持间隔 |
| 02 | 主核与两段倾斜错位星弧 | 两段存在光传递相位差 |
| 03 | 曲折自然分枝、松散边缘 | 小幅舒展回聚 |
| 04 | 粒子形成的窄纵向亮缝 | 局部流光沿缝经过 |
| 05 | 主簇及偏移稀疏残迹 | 残迹比主体更慢消退 |
| 06 | 偏离群落重心的稳定独核 | 外围不对称运动 |
| 07 | 细长、有方向的星流 | 外段更活跃，近核收缓 |
| 08 | 淡紫断续弧 | 较慢余辉恢复 |
| 09 | 三层疏密交替薄尘 | 不同深度轻微错动 |
| 10 | 不对称小片碎星、少量暖白 | 短响应、较快恢复，不作烟花 |

共享材质，区别来自分布、局部流向、相位及恢复时间，而不是十套独立场景或整体加亮。星流采用局部位移与明度传播的艺术表达，不宣称每颗首页粒子都物理迁移到星图，也不宣称与音乐频谱同步。

## 实际验收

本机 Apple M2，Chrome `155.0.8059.80`（ANGLE Metal Apple M2）与 Playwright WebKit `26.5`（Apple GPU），均实际启用 WebGL。视口：1440×900、390×844、360×740。

本地与预览分别完成两引擎 × 三宽度，每组29项检查。额外覆盖强制无 WebGL 和实际上下文丢失。测试结果与具体断言保存在下方 JSON。

- 桌面、移动视口自然纵向推进；慢滑、快滑、停止、反向及入口点击可到达同一终点。
- 四个交接状态中，支流曲线端点对应源头投影与第一首实际位置；停止后曲线保持稳定；没有重播开场或重建几何来恢复状态。
- 十首顺序正确，全部可定位/进入；中文、英文及韩文的实际字符矩形均在视口内，无横向溢出。
- 定位第一首不会落回未开放交接区。快速索引、背景锁滚、Escape/遮罩关闭、键盘焦点通过。
- 触摸模拟纵滑不误开；第08首进入详情后返回保持纵向位置（390px录屏：3332 → 3332）。桌面录屏返回3586 → 3586，末段及中段另外复验。
- 同一节点浏览、聚焦、点击短转场位置不漂移。
- 精选音频真实播放、返回星图后单实例续播、迷你播放器暂停收起、其它作品30秒试听启动通过。
- 系统与站内减少动态设置、静态纵向星图、直接链接、返回及上下文丢失降级通过。
- 减弱模式保留完整形态，按输入绘制；离屏/离开页/模态打开停止不必要绘制，GPU资源与监听释放。
- 残迹检查：离开第05、08首约170ms后，主响应约0.31/0.25，余迹约0.61/0.56；随后回落到0.02以下，未累积亮度。

录屏复验曾遇到一次返回位置断言失败，固定等待不能可靠代表平滑定位已结束；测试改为观察滚动实际稳定200ms后记录位置。最终桌面及移动录屏均通过，网站代码未为此变更。此前失败的单次根因未能独立稳定复现。

实际执行：`npm run typecheck`、`npm run build:production`、10项模型/音频服务单元测试，以及 `verify.cjs`、`handoff.cjs`、`record.cjs`、`echo.cjs`、`performance.cjs`、`handoff-performance.cjs`、`edges.cjs`、线上 `verify-http.py`。
仓库无独立 lint 命令，未声称 lint 已通过。Three.js 共享 chunk 仍有大于500kB的构建提示；新星图渲染模块约13kB量级，没有新增大库或后处理。

## 性能条件与限制

每个视口分别对星图闲置/滚动、交接停留/正反滚动各采样4秒。最终本机 rAF 间隔 P95 为16.7—16.8ms，未记录大于34ms间隔或 Long Task。星图CPU提交P95约0.4—0.6ms；这不是GPU帧耗时。

星图桌面23081点、手机14831点，包括桥接支流；2个批量绘制调用。相比V1.1提高了局部材料预算，同时减少背景余星、重新分配亮度/分布并降低手机DPR上限至1.5。没有将画面整体曝光提升作为升级手段。

手机视口闲置约30次绘制/秒，滚动事件后120ms内优先跟随原生滚动调度；停止后回到低频。短时采样中几何建立次数保持1。首页和星流仅在交接期间同时绘制，星图稳定后首页停绘。粒子缓冲不逐帧全量上传。

**未验证真实iPhone、实体触控板手感、长时间发热/低功耗状态及低端设备GPU表现。** 移动录屏使用Chrome CDP触摸事件，是模拟输入，不能称为真机验收；WebKit测试也不等同iPhone Safari实机。录屏编码帧率不是网页渲染帧率。本轮未获得指令中提到的约12秒录屏文件，问题定位来自实际源码和可运行页面。

## 对照与差异

保留首页现有构图与真实半扭转模型。参考图用于“源头—连续交接—纵向展陈”关系，没有复制它的三栏网页形式、小型旋涡、夸张星芒或错字。实际主星链和星象比参考图更收敛，文字与触控区留有暗区；桌面围绕中部展开，手机标题放在星象下方，而非照搬长图比例。

首页至星图仍沿现有双渲染器架构实现，使用共享路径与单一滚动进度协调，不大规模合并全站渲染器。桥接粒子连续保留至第一首，进入星图后继续随文档上移，不以全屏淡出/淡入遮掩接缝。初始首页静止状态保持原模型，只有滚动开始后才引出支流。

视觉是否优于V1.1仍等待用户验收；本轮未发布到正式站。
